# 核验约定

适用：每次文档或获批实现改动。当前仓库仅有 Markdown；本文件是检查方法，不是已运行测试记录。活动结果只写入 [AI_BOARD](../../AI_BOARD.md)，技术规则只维护于[技术母本](../docs/architecture.md)。

## 当前文档检查

1. 对照批准范围逐个核对文件清单；只有本轮10份 Markdown，保留原有用户内容，不提交源 DOCX/PDF、二进制、凭据、私人原始记录、临时日志或审计脚本
2. 以 UTF-8 读取所有文件，检查结尾换行、不可见替换字符、NUL、闭合代码围栏和 JSON 示例语法；计算每个文件的 SHA-256 与 Git blob SHA-1
3. 解析所有相对 Markdown 链接，按链接所在文件解析路径并限制在仓库内；锚点按 GitHub 标题规则（小写、移除标点、空格转连字符、同名加序号）核对实际标题。外部参考链接保留不代表当次联网核查通过
4. 逐行审核分层契约的职责/禁责、计划路径、输入输出、允许/禁止依赖、状态归属和验证方法；下表用于识别违例，不新增第二套架构
5. 核对唯一母本：架构规则只在 architecture；叙事共约只在 outline；人物设定、首章与关键场景各归对应文件；活动状态只在 AI_BOARD，MEMORY 只留决定。检查跨文件的状态、授权范围和待确认假设是否一致
6. 全文扫描本地绝对路径、私人邮箱/联系方式、凭据特征、私钥头、访问令牌和私人原始叙述，并人工复核命中；无命中是有限检查，不是保证不存在一切敏感信息。叙事文本为已获准公开的原创虚构人物，不以技术设定推定真实个人经历
7. 四份叙事转换稿初始化时逐字保留；技术稿仅整合获批契约及必要状态修订，并记录变更原因。拒绝衣装或亲密互动不扣关系、不阻断主线；不添加血腥、露骨内容、剂量模拟或医疗解锁恋爱
8. 发布前重新检查远端，确认不会覆盖新出现的用户内容；发布后读取最终 main ref、commit/tree 以及各文件完整内容，以 UTF-8 字节、大小、SHA-256 和 Git blob SHA-1 对比本地集合。只读权限或写入请求成功不能替代回读证据；不使用 force 推送

## 边界与状态检查

所有源码位置均为计划。当前逐条对照技术母本查文档一致性；代码获批且存在后，再用全文搜索和代码/场景解析落实下列检查，不能仅凭目录名判断通过。

| 检查对象 | 当前可查证据 | 实现后的必查方法 |
| --- | --- | --- |
| 展示与场景 | 不承诺直接修改剧情、奖励或存档；输入输出是意图、视图与演出回执 | 搜索所有 preload/load、class_name 类型、场景脚本与动态路径；禁止依赖适配器及领域写入口，重绘无副作用 |
| 应用与领域 | 应用只依赖领域与边界；领域不依赖节点/UI/文件/应用 | 静态扫描加人工追踪动态引用；领域测试无需节点树/渲染/文件；应用不得构造具体 IO 适配器 |
| 边界、适配器与装配 | 契约不依赖具体 IO，适配器不决策剧情，只有 bootstrap 负责装配 | 检查依赖边方向与反向 bootstrap 引用；替身注入加载/文件失败；启动失败不留半初始化世界 |
| 唯一状态权威 | StateStore 是剧情/任务/库存/关系/恢复锚点唯一写入口，展示仅局部表现 | 追踪全部写操作；禁可变内部 Dictionary/Array 泄露，检查只读/隔离快照，事务整批成功或零变更 |
| 命令与旧回调 | command_id、指纹、修订、会话及交互代次完整，幂等账本随状态保存 | 双击、换 ID 重复选择、同 ID 改载荷、旧演出回调、取消后完成回调；断言一次逻辑选择只消费一次 |
| 内容与资产 | 稳定 ID、条件/效果白名单，数据与运行状态分离 | 重复/悬空 ID、出口/可达性、缺文本、任意脚本拒绝；来源与许可清单复核 |
| 存档与切换 | 离场保存→目标稳定→新锚点保存，失败恢复及锁释放均有定义 | 中断注入每个写入/替换点，检查跨会话槽位写序号、读旧档/新游戏的队列屏障、旧会话写入被拒、合法低 revision 新快照可保存，以及正式槽最终回读校验、未知版本拒绝和有效备份 |

## 未来测试入口

下列均为计划路径，目前不存在、未运行；产品实现须另行批准，不能为文档验收伪造脚本或 CI。落地后记录真实引擎路径、版本、命令、退出码与报告，再允许把命令放进可执行说明。

- tests/content/validate_content.gd：稳定 ID、引用和白名单

无图形测试不能代替 GPU 渲染；版本命令不能证明项目可运行；编辑器运行不能证明 Windows 导出；Steam 目标不能证明发行审核通过。

## 报告格式

- 范围与实际文件：列明发生的修改和未扩大的范围
- 已通过：写检查方法、实际结果与证据；涉及发布写最终分支/提交链接及回读哈希结果
- 失败：明确预期与实际差异，修正后重测受影响项
- 未执行：明确尚不存在的工程/脚本或不属于本轮的测试，不记作通过
- 受阻：写确切访问/工具/授权限制，不以其他身份或仓库绕过
- 剩余风险：列仍需作者决定或实机验收的事项；同步 AI_BOARD，避免在 MEMORY 新增第二份待办
