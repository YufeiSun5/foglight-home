# 单个机械工坊：Blender → Godot 验收

这是项目验收流程，不是 Tripo 能力保证，也不声称已经跑过。先读项目 AGENTS.md：重 Blender 任务按现有锁与线程限制；GUI、场景文件由项目负责人操作；保持原始候选和失败证据。

## 官方 cookbook 的可复用顺序

来源：[GPT-6 Astra 3D 游戏场景工作流](https://developers.tripo3d.ai/zh/cookbook/gpt-6-astra-3d-game-scene-workflow)，页面日期 2026-09-18，核验 2026-10-09。页面正文由官方站点前端资源提供，普通 HTML 抓取可能只返回空壳。

其流程是：分层拆出资产清单 → 灰盒确认尺度、路线和相机 → 先试一个核心建筑 → 替换占位 → 布局稳定后调光 → 在引擎内实际走一遍。模型逐个检查材质通道、孔洞/交叉几何和角色碰撞；有问题的资产单独处理。

本项目采用上述顺序，但限于已授权的一栋主屋，不自动扩为整城或批量生成。资产清单先列主屋与已允许附属件，记录引用图、使用位置、重要轮廓和独立碰撞需求；保留灰盒，首个候选经过下述验收后才决定是否继续。收费重试须符合现有预算及授权，不因教程建议而自动执行。

教程目标引擎是 UE5：其中 Nanite、Unreal MCP、First Person feature pack 不是 Godot 功能，也不能作为本项目性能证据。H3.1 高面数/8K 与 P2.0 的教学分工仅供选型参考，不直接照搬到本工坊预算；Godot 需按实际画面尺寸、材质和 LOD 验收。其旧认证命令示例也不覆盖当前 CLI 契约，接入按 [官方 CLI 路线](cli-access.md) 与安装版本内置文档核实。

## 输入与路径选择

参考图仅用于理解单个主屋及允许的前景。分开标记屋顶外形、主屋体积、门窗、烟囱、附属机械轮廓与被遮挡部分；不要把人物、背景山体、整片地面作为建筑网格的一部分。多视图中的背面设计属于推断。

单图→模型可作为较少收费步骤的候选；单图→多视图→模型可先人工核对跨视角一致性，但多一道生成并不保证几何准确。根据获批实验方案选一条，避免默认全跑。先看屋顶与主体大轮廓，再判断细节。对非对称房屋不要擅自启用对称或自动补全来掩盖错误。

## Blender 实际检查

1. 原始模型只读留存；导入工作副本，保存可编辑 .blend 和各贴图，不仅截图。记录输入/输出 SHA-256 与工具版本。
2. 以实际导入数据检查：对象/材质数量、三角化后的 triangles/vertices、尺寸与轴向、法线、非流形/退化面、孤立漂浮块、重叠内壳、UV 与材质引用。不要用 face_limit 填“实测三角形数”。
3. 灰模检查屋顶、墙体、门洞、烟囱、人物相对高度。需要可进入/可活动部分时，真实几何与分件必须核实；贴图里的门不等于门洞。
4. PBR 检查：底色不应携带强固定投影或高光；normal 的方向与色彩空间、roughness/metallic 的数值语义正确；金属只分配合理部位。记录实际贴图分辨率、位深/压缩、材质槽。API pbr=true 不替代这些检查。
5. 用相反主光方向和中性环境各拍一组，再看暗面是否仍固定发黑；禁用贴图也检查真实立体感。去光照失败时明确标注；需要重新收费贴图必须另有批准。
6. 保留高模；根据轮廓与运行环境确定减面目标，再实际生成/检查 LOD。记录每级三角形数与轮廓变化，不只写百分比。重拓扑后的 UV/贴图要重查，必要时本地烘焙并检查接缝。
7. 碰撞单独构建：静态主屋优先满足玩法的简化碰撞；可动件用适合动态对象的形状。确认门口可通过、屋顶/地面不误拦人；不默认把高模全用作碰撞。
8. 导出 Godot 支持的实测格式；GLB 可作为自包含候选。显式记录米制尺度、底部轴心、朝向和贴图打包，重新导入一次验证依赖完整。

## Godot 原生验收

在本项目实际渲染器和场景中打开，不以 Blender 渲染或 headless 成功代替。匹配现有相机和人物尺度，拍固定机位的原生帧；至少检查正面及侧/背角、两种光照、LOD 切换、近景接缝和遮挡关系。运行人物碰撞/绕行检查，验证贴图颜色、法线、阴影和透明材质。

性能记录须注明设备、Godot 版本、渲染器、分辨率、相机位置、场景条件与采样方法。填写实测帧时/帧率、draw calls、显存或纹理占用（工具可得才填），以及导入 triangles、材质数与纹理尺寸。缺少设备或计数器时写“未测”，不推算成实测，不把理论 LOD 预算包装为达标。

## 交付与通过判定

交付原始生成物、编辑 .blend、材质贴图、导出网格、LOD/碰撞资源、Godot 场景引用、固定视角原生帧与简短验收表。表中分别写：参考匹配、几何可用、可重打光、导入完整、碰撞正确、性能实测，各为通过/失败/未测并附证据路径。仅 API success 或图片好看不能判定整项通过。

本轮文档创建时没有执行 Tripo 生成，也没有新增 Tripo 模型的 Blender/Godot 测试结果。
